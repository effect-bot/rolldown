# Effect service shaking — Implementation

> The rationale and principles behind this live in [design.md](./design.md).

## Summary

The pass is one link-stage step, `LinkStage::effect_service_shaking`. It is called from `link_stage/mod.rs` after `cross_module_optimization` and before `include_statements`. It binds the Effect model to the bundle's `effect` modules and generates constraints for every other module. Then it solves one worklist, turns per-key demand into property removals in the module ASTs, and patches `StmtInfo` so Rolldown's tree shaking drops what the removed methods were the only users of. It is enabled by `experimental.effectServiceShaking` and does nothing otherwise.

## Files

All of it is in `crates/rolldown/src/stages/link_stage/effect_service_shaking/`:

## Data flow

1. **Find and bind.** For every `MODULES` entry, the pass resolves the public `effect/<Module>` module in the graph and its exports. If `effect` is external, or a ruled export is missing, or the major is not `SUPPORTED_MAJOR`, it warns and returns. The modelled set is the public modules plus the owners of their ruled exports' `alias_chain`s. The binding walks modules in execution order, but precedence does not depend on it (`BindRank`): an explicit rule beats a declared Key, which beats the default. At equal rank an export's own declaration takes its spec and the declarations it aliases keep what claimed them first. So `internal/effect.js`'s `map`, walked before `Effect.js`, first takes the default as that module's own export, and `Effect.map`'s rule then replaces it. Ordinary code that imports `internal/effect.js` directly, as Schema does, hits the stable rule. Every export of a modelled module is bound to one of three things, in `Shared::rule_symbols`: its `Spec` object, a declared Key, or `effect::default_object` (the `effect:default` rule). An export that aliases ordinary code is linked to that code instead.
2. **Generate.** Each non-modelled module's AST is walked once by `Gen`. Modelled modules are skipped entirely: their bodies sit behind rules.

   A top-level statement of a non-entry module is lazy when Rolldown's `StmtEvalFlags` find no side effect, it declares symbols, and it is not an import or a re-export (`LinkStage::lazy_statements`). `Gen::program` puts a lazy statement's constraints in a body of its own (an `FnInfo` with no params), and `Shared::lazy_decls` maps each symbol it declares to that body. `Gen::symbol_var` records every reference with the body it appears in (`lazy_refs`: the function being generated, or the lazy statement for top-level code). Once all modules are generated, each reference to a lazily declared symbol becomes a `Pending::Activate` in the referencing body, so the statement is installed when that body is. A module namespace activates the statement behind an export read by name (`Analysis::lazy_exports`, including exports reached through `export *`) and all of them on wholesale use (`lazy_namespaces`: unknown-key reads, enumeration, contents, spread, escape). Symbols read outside generated code are activation roots: entry exports, and analysed code aliased by model-bound declarations.

   Every walk over modules (namespace objects, binding, generation, namespace exports) goes in execution order (`exec_order`, ties by `stable_id`), and every walk over a module's exports goes in name order (`sorted_exports`). `ModuleIdx` follows the order modules finished loading, which differs between builds of the same input, and `resolved_exports` is a hash map. The walk order matters because the solve is first-come: the first `MAX_CLONES_PER_FN` call sites to reach a function get clones and later ones share the body, and later calls of a builtin at one site merge into its first invocation (`rule_memo`). Another order gives another sound but differently precise constraint set, and can go over the budget where this one does not.

3. **Solve.** `Analysis::solve` runs the worklist to a fixpoint. Calls to a builtin object run its rule. Calls to a closure activate the function and install its pending constraints. `new F(...)` on a function constructor makes one instance per function, with `F.prototype` as its prototype, and runs the body with that instance as `this`. An ordinary function's `prototype` is a default object (`Analysis::function_prototype`), whose `constructor` is the function, until code replaces it. A class's prototype has `constructor` set to the class. `super.m()` looks `m` up on the parent prototype (the parent class itself in static code) and calls it with the current `this`. A class getter or setter runs with `this` holding its declaration target and every object that inherits from it, directly or through a chain (`Constraint::Inherits`, tracked when an object's prototype variable is created, and `Constraint::Accessor`); a setter's parameter also receives what is written under its name on those objects. Accessors therefore run once for all their receivers, not once per receiver. `new C(...)` on a class makes one instance per class and runs `Analysis::construct_on` on it. A class with a constructor runs it; `super(...)` in it runs the parent constructor on the same `this` with `super`'s own arguments, and `this` then also holds what the parent yielded. A derived class without a constructor runs its parent's construction on the instance with the `new` call's arguments, as JavaScript's implicit constructor does. Every level passes up the objects a constructor returns, so a replacement object reaches the `new` result and the derived `this`. The instance stays among the results. A function marked `cloneable` is cloned instead, once per call site. Cloneable means a leaf `Normal`/arrow function with at most `MAX_CLONE_PENDING` pending constraints, marked by `Gen::mark_cloneable`. Clones are capped at `MAX_CLONES_PER_FN` per function and `MAX_CLONE_DEPTH` levels. A clone renames its own variables and locals, tags its call sites with `CLONE_SUB` and shares everything it captures. A wrap (`Analysis::wrap_of`) calls its callbacks from a sub-site of the rule call that made it, so builtin callbacks get one rule invocation per wrap. Closures handed to wraps share one clone per function (`WRAP_CLONE_SITE`); a clone per wrap exhausts the budget. `over_budget` checks the object, variable and points-to entry counts on every round. Over budget, `bail_everything` runs and every method is kept.
4. **Demand.** A read on the value of key `K` adds the name to `K`'s demand. Unknown names, enumeration, escapes to opaque code and reflection on a Context, Layer or Runtime internal bail the key, or every key the object may hold. `Analysis::key_is_bailed` also honours `never_prune` and `bail_all`.
5. **Prune.** `prune.rs` considers only object literals that reach a key's value, directly or through spread sources. Their method properties not in the demand set are removed, provided the initialiser is pure and TDZ-safe. Local `const`/`let` bindings that only removed properties used are deleted. Then `StmtInfo.referenced_symbols` is patched. Top-level statements are never removed by the pass.

## Debugging

Environment variables, all opt-in:

- `ROLLDOWN_EFFECT_SERVICE_SHAKING_REPORT=1` prints the per-key summary (providers, removed and kept methods, bail reasons), plus the solve statistics.
- `ROLLDOWN_EFFECT_SERVICE_SHAKING_DEBUG=1` adds phase timings, the module index table, solver histograms during the solve (loads by name, calls by module, the fattest variables).
- `ROLLDOWN_EFFECT_SERVICE_SHAKING_MAX_{OBJECTS,VARS,ENTRIES}` override the budget (defaults 3M objects, 30M variables, 32M points-to and copy entries; the entries default was raised from 16M on Tim's decision of 2026-11-06). The hidden `experimental.effectServiceShakingMaxEntries` option sets the entries budget for one build; the variable overrides it.

## Current status

- Escape rules (issue, "Code the pass can't see"): `Analysis::escape` hands over ordinary values only. A service reached through them keeps every method (`demand.all`), and later stores into an escaped object escape too. Effect's containers, keys and Effect primitives escape as nothing, a module namespace escapes as its exports, and an effect built by unseen code runs without a bail. For `o.m()` into unseen code, `Constraint::EscapeReceiver` hands over only the receivers whose own `m` slot can hold that code (`EscapeIfOpaque`), or that have no own `m`. The call's property name comes from `Analysis::method_names`, filled by the generator; clone sites are not listed and hand over every receiver. A key whose values include an external value no longer counts as fully demanded (`prune.rs`).
- Public types (issue, "Assumptions" 2): `Analysis::exits` marks the model Effects whose public type is `Exit`, and only those resolve `Exit.{_tag,value,cause}`. `Effect.exit`, `onExit`, `runSyncExit`/`runPromiseExit` (both forms), `Fiber.await`, `addObserver`/`pollUnsafe` and `acquireUseRelease`'s release produce Exits rather than Wraps. `ManagedRuntime`'s remaining public members (`dispose`, `disposeEffect`, `scope`) have rules, so reading them is no longer reflection.
- Containers (Tim's decisions under "When a method is kept"): `load_name` resolves a named read on a Context, Layer, ManagedRuntime or MemoMap through its public-member rules only, and reads nothing otherwise; unknown-name reads, writes, enumeration, iteration and spread on them do nothing. `Context.mapUnsafe` has no rule, so it reads nothing (the view rule, `view_of` and `bail_view` are gone), and neither do MemoMap members. `contents_of` on a container looks up the services of its keys. `Context.get`/`getOption`/`getOrElse`/`getOrUndefinedUnsafe` go through `Constraint::LookupIn`, so a key's services flow only when the Context argument may be a Context (a model Context, an unknown value or a wrap). `ManagedRuntime.cachedContext` reads as a Context of the runtime's keys, and a write to it provides. With every container bail gone, `KeyUse::Bail` and `bail_object` are removed.
- Effect's formatting and structural equality (design principle 9): `Analysis::ignored_pool` (`Walk::Protocol`) and the `effect:Equal.equals` and `effect:Hash.hash` rules feed `Constraint::Walk`. `Analysis::walk` copies an object's fields, later fields (through `unknown_loads`, without `demand.all`), elements, spread sources and prototype into the pool. It also loads each protocol method by name and calls it with the object as `this`. `Constraint::Witness` collects the objects that have an `[Equal.symbol]` for that method's argument.
- Pipe forwarders: `generate.rs` binds a function whose body is exactly `return pipeArguments(this, arguments)`, with `pipeArguments` bound to the `Pipeable.pipeArguments` rule, to the `effect:Pipeable.pipe` builtin (`Gen::pipe_forwarder`). A lookalike with a local `pipeArguments` stays a closure. `load_name` gives builtins `.call`, `.apply` and `.bind` as it gives closures, so `forwarder.call(other, f)` reaches the rule with `other` as `this`.
- The error channel is not tracked (Tim's decision, assumption 3): every model Effect shares one failure slot (`failure_sink`) that nothing reads, and `failure_of` yields nothing, so `catch*`, `catchDefect`, `mapError`, `tapError`, failure branches and `Exit.match` handlers still run but receive no input. `Exit.cause` yields nothing. Cause's functions (`LISTED_MODULES`, `effect:Cause.inert`) read nothing, return a plain value and run the callables they are given with no input. `Cause.done`/`Cause.Done`, the signal a Schedule (or any Pull) ends with, are no exception: no service is a `Done`'s value (assumption 4), so `Cause.done`'s value is ignored, `Cause.Done` is inert, and handlers get no failure input at all. The program-wide `Done` pool (`done_values`, `done_failure`) was removed with Schedule stepping. The per-wrap Cause read-back (`cause_of`, `transparent_wraps`) and the stable Cause predicate and `fromReasons` rules are gone. Host protocols and logs: `Effect.annotateLogs`'s values are ignored (`unknown`): they go to the protocol walk, and `References.CurrentLogAnnotations` holds none of them. `Effect.log` calls the installed loggers (`Logger.CurrentLoggers`, whose `Logger.make` objects have a `log`) with `{ fiber, date, logLevel, message }` and an empty message; the messages (`ReadonlyArray<any>`) go to the protocol walk (`run_loggers`). `Tracer.make` runs a bundled Tracer's `span` with inert options, then the span's `end`, `attribute`, `event` and `addLinks` with inert arguments, and `context` with no primitive (`effect:Tracer.make`). `Constraint::Protocol` also runs the protocol methods during the solve: string conversion calls `toString`/`valueOf`/`[Symbol.toPrimitive]` on the value, and `JSON.stringify`/`console.*`/`util.inspect` feed the program-wide `Walk::Json`/`Walk::Inspect`.
- `Scope.forkUnsafe` (`MODULES`) returns the parent scope, so a child's finalizers run on an explicit child close and on the parent's close.
- Type bounds (design section 8): `mod.rs` records the exported functions of the modules analysed under the service-constructor exception, with the `.d.ts` beside each (`exported_functions`, including the body passed to `dual`); `Analysis::bounds_of` resolves one when it is first called. A bounded parameter or return is a `Constraint::FilterCopy`: `admits` passes what the declared type can hold, a summary at a primitive-only position becomes `top_host`, and a rejected object waits in `rejected` until a field, prototype, accessor, unknown store, spread source or escape changes it (`recheck_tree`; `heirs` is transitive), with a final check when the worklist empties. The debug report prints the resolver's cost and, when the budget stops a solve, what each service demanded at that point.
- Direction 2 (Tim's decision of 2026-11-07): calls into type-modelled code track only what may hold a service, and hand everything else to code the pass can't see.
  - Admission (`Analysis::admit_typed`, `Constraint::AdmitTyped`): at a position whose declared type mentions a type parameter (`Dts::generic_positions`), a value enters the call's slot as itself only if it reaches a value provided under a key that may be pruned (`prunable_service`), a key, a class or a generator, looking through records, arrays, closures' fields, Effect successes, promise values, wraps and slots (`may_hold`). Anything else escapes with `Flavour::Ext`: effect code holds it, its functions run with unknown arguments, and a service stored into it later bails. Every slot holds `top_ext`, so whatever the caller does with a service-free value it gets back is what it would do with a value from unseen code. Whatever this test answers is sound; it only trades cost for precision. An Effect, promise or type-modelled result (`ObjKind::Typed`) is tested when the solve settles rather than when the handover is met, so one whose contents arrive later (a fiber handed to `addObserver` before its Effect has run, `Stream.make(store)` handed to `Stream.run` before the record reaches its slot) is admitted whatever order the solve met the two in. Each settle round walks a value once however many sites hold it back. Admissions come first and the solve runs again after each round (`settle_admissions`), so what one admission hands on, such as the success of another waiting value, is seen before anything is given up. Only at a fixpoint with nothing left to admit do the values still waiting go to effect's code, all at once (`release_admissions`), and they keep their `EscapeOut` subscription for anything they come to succeed with later. Records, arrays and functions are still tested at the handover: testing them at the fixpoint too grows `distilled_stripe` from 0.8M to 7.6M entries, past the budget.
  - Concrete positions join no slot: their callbacks run with unknown arguments, keys handed over bail, and a program object has the members its declared type names read (`typed_concrete`). A result of a concrete type is a summary holding nothing (`RetShape::concrete`).
  - Callbacks run as code the pass can't see runs them (`typed_callback`): once per function, with unknown arguments; what they return, and what an Effect or promise they return succeeds with, goes to unseen code (`Constraint::EscapeOut`). A callback declared, in every signature the call may match, to return a value that holds no service goes there without its return (`Dts::callback_free_returns`). That is a primitive (`Predicate<A>`, `Refinement<A, B>`), a type parameter whose every other occurrence in the signature is in a service-free container's type arguments (`Schedule.map`'s `Output2`; `Dts::container_only`, `effect::SERVICE_FREE_CONTAINERS`), or an `Effect` that succeeds with one. The callback still runs, and so does an Effect it returns. Its return goes once the same function is handed over anywhere its return is open, before or after (`Analysis::escape_with`, `release_ret`); until then effect's code writes nothing into it, since its declared function type has no properties. A service the call holds bails when a callback parameter of a type parameter's type could receive it (`Dts::callback_masks`, from the declared callback types and type-parameter constraints). Running callbacks with the slot instead (`ROLLDOWN_EFFECT_SERVICE_SHAKING_TRACKED_CALLBACKS=1`) merges every call's slot into every callback and does not finish on the OpenAI gate.
  - Containers: one pool per module (`typed_pool`), written by calls whose declared shape may store an argument into a value another holds (`Dts::container_shape`; method calls only for modules that declare a storing method, `Dts::methods_store`), and read by calls that may hand a container's contents back. A data-last function handed as a callback routes the call's values to its export's pool (`pool_route`). A call with no signature (a method, a value of unknown origin) hands what it holds and is handed to unseen code. Calling a value an export returned uses that export's returned signature (`Dts::returned_call`). A `pipe` member read is `Pipeable.pipe`; a name a module declares only as a method holds no slot value (`Dts::method_only_names`); a store into a summary goes through admission.
  - Constant keys: an export of a type-modelled module declared as a top-level `const` holding a string literal or `Symbol.for` of one (`Equal.symbol`, `Hash.symbol`, `HttpServerRespondable.symbol`, `Redactable.symbolRedactable`) binds to that key, as `Analysis::str` names it, not to a summary (`LinkStage::constant_key_of`). An export reached through value aliases (`alias_chain`, with imports and re-exports already resolved) binds only if every hop is a top-level `const` (`LinkStage::constant_key_through`): a `let` or `var` on the way may be written after its initialiser, so it stays a summary. As a summary its value was no name, so a computed member written with it (`{ [Equal.symbol]() {} }`) was a store under an unknown key: the admission filter put `top_effect` in every field of the object, and calling any method of a service built that way handed the service to effect code. The protocol walks load these members by the same names (`EQUAL_KEY`, `REDACTABLE_KEY`), so the methods they call run with the service as `this`.
  - The same lever applies to the protocol walks and host adoption (a value that reaches no code is not walked or adopted until it does: `reaches_code`, `Deferred`) and to unknown-key stores and host builtins that copy structure (`admitted_values`).
  - A filter variable (`filter_vars`) holds `top_effect` only once something is held back from it, and primitives pass through it as themselves. Seeding `top_effect` up front made every value read through the filter callable as effect code, so calling a method read from a prototype that a dynamic store had written handed its receiver to effect code (`receiver_context_limit`). A boundary's opaque value (a class or module hole) passes as itself: calling it with a service promotes or bails that code, and holding it back would hand the service to effect code instead. Enumerating an object's values (`Object.values`, `Object.entries`, `Object.getOwnPropertyDescriptors`) lets the program's own functions through (`admitted_callables`), and `Array.prototype.map` hands its callback the elements as they are, as `forEach` does: a function read back that way is called by the program, not by effect code (`lazy_toplevel_activation`). Letting functions through every filter instead runs Stripe over the budget (7.7M entries).
  - `push` and `unshift` store their arguments as index stores (`arr[i] = x`), so they never become a named property such as `map`, and they return a number. As unknown-key stores, the hook a module registered was also read back as `hooks.map`, and through the filter that read was effect code.
  - Service constructors (option (b)): `mod.rs` selects by type (`Dts::constructed_shapes`) the exports that take an implementation (a function, or a type naming the returned key's interface) and return a key's shape, or an Effect or Layer of it. Their modules, and the internal modules they import, are analysed as ordinary code; the report lists the matches. Such a key prunes unless a called type-modelled module imports the module declaring it, in which case it keeps every method.
  - Diagnostics: `ROLLDOWN_EFFECT_SERVICE_SHAKING_OPAQUE=1` (every type-modelled call is an opaque host call, the Architect's bound A), `ROLLDOWN_EFFECT_SERVICE_SHAKING_SKIP_CONSTRUCTOR=<substring>`, `ROLLDOWN_EFFECT_SERVICE_SHAKING_CLONE_SITES=1`; with `ROLLDOWN_EFFECT_SERVICE_SHAKING_DEBUG=1` the report prints a census (pools and their writers, largest slots, hot call sites, callback runs). The stand-in machinery (`StandIn`) now serves only unknown-key stores.
- Type-modelled library modules (design principle 11) are the only model of `effect` since the switch-off cut; the last commit with the internal analysis is tagged `effect-service-shaking-dual-mode` (`b6d9504e`). `mod.rs` first checks that every module of `effect` in the bundle has a readable `.d.ts`; if one doesn't, it warns and returns, so every method stays. Then `mod.rs` collects them (`typed_modules`) and binds their exports to `Analysis::typed_export`; `heap.rs` has `ObjKind::Typed`, `typed_call`, `typed_arg`, `slot_in` and `typed_member`; `dts.rs` adds `Dts::ret_shape`. When it was introduced (still opt-in), 163 of 201 fixtures passed against 169 with the internal analysis. At the cut, 217 of 237 fixtures pass. The 20 red ones keep a method they should remove; none removes a method the program reads.
- Fixtures: 176 of 201 pass. `dual_arity` passes: `Function.dual` records a literal arity on its `dual.fn` builtin, so a full call never also mints a partial; a predicate arity keeps both branches.
  - Prefix narrowing (`dynamic_key_prefix`): a template literal or `+` whose leading part is a constant string and whose rest is computed at run time (`Gen::run_time_string`, `const_prefix`) is one host string per prefix (`Analysis::prefixed_host`). As a key's name it looks up only the keys whose names start with the prefix, plus the keys whose name is unknown (`prefix_key_use`); any other use of it is every key, as before. A key created later that matches the prefix joins the lookups already made (`prefix_lookups`, in `key_value_var`).
  - `decode_transformation_value` is green. A decode callback handed to `SchemaTransformation.transform` returns the service, and the program calls a method on the decoded value. Five rules carry it. (1) A name declared both as a function and as an interface (`Schema.decodeTo`) takes its signatures from the function (`Index::funcs` in `dts.rs`); the interface used to shadow it, so the `pipe` call had no signature and handed everything to unseen code. (2) An arrow callback reads only the parameters it declares (`declared_args_mask`), so a callback parameter it never declares does not bail a service. (3) A closure's return joins the call's slot (`Constraint::SlotIn` with `top_effect`) instead of escaping (`EscapeOut`), so the decoded value is the service. Functions handed at a type-parameter position, alone or in a record, go without their returns, which `typed_callback` tracks. A record or array handed to effect's code holds its functions' returns back as a closure does: its fields escape without their returns (`Constraint::EscapeHeld`, from `escape_with`) until it is handed where returns are open (`release_ret`). (4) Calling a method on a function effect's code made (`top_effect`) hands over only the receivers whose own slot can hold that code (`EscapeReceiver`), as for any unseen method, and a summary is not handed over through a function it holds as a type parameter's value (`escape_receiver`). (5) A method call on a summary with no signature hands over only the receivers whose member of that name may be the summary (`Constraint::TypedReceiver`, `TypedReceiverIf`), and one with no arguments hands nothing to unseen code. Cost: with rule (4), `distilled_stripe` sees an `annotations.js` value (distilled's `evalEntry` can return what `getAnn` returns) reach `Effect.serviceOption`, so that module hole is analysed in a second solve. The size is unchanged (5.7% smaller); the gate takes 2 solves and 1.61M entries, about 1.8 s against 845K entries and 0.62 s before.
  - Service-free containers (assumption 4): `effect::SERVICE_FREE_CONTAINERS` lists the public types no service passes through, today only `Schedule`. `Dts::container_only` finds the type parameters a value of which is in a call only in their type arguments, scanning the signature's parameter and return types and, for a function a call returned, the parameters of that call (`Sig::outer`, so `Effect.repeat(schedule)(self)` sees the Schedule in the outer call). A return of one, or an `Effect` succeeding with one, is an unknown value that holds no service (`RetShape::free`, `effect_free`; `top_host`), so a string among them may still name a member.   - Arrays keep index elements apart from stores under keys that may be names (`named_elem`): a named read (`arr.then`, `arr.toJSON`) sees the latter. Effect's own members (`~effect/...`) are written only by code naming them, never by stores under computed keys.
  - Exact relay removals: a protocol call's result goes straight to the walk pool, and `Pipeable.pipe` steps chain their own results. Only an allowlist of inert host methods is skipped by protocol walks.
  - `Function.prototype` is the host prototype (`call`/`apply`/`bind` rules), not code the pass can't see. A hand-written thenable and a descriptor `set` are program code the pass does not follow (the opaque boundary), not unseen code.
  - A removed method's own binding (`const m = () => ...; Store.of({ m })`) inside a function is removed with it when nothing else references it, so what only it referenced can be dropped by the bundler.
